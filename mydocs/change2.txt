The diagnosis
There were two separate bugs producing your bad output, not one.
Bug 1 — infrared was set as primary token by the Claude pre-call. This is wrong for this query because infrared describes how the system works, not what it does. The previous identify_primary_token.txt prompt didn't distinguish between "the technology used" and "what is novel." The updated prompt now explicitly says: "Common sensor types (infrared, lidar, radar) are primary only if the sensor itself is the invention. If the invention is a SYSTEM or METHOD using a sensor, the system/method concept is primary." Claude will now return lane detection as primary for this query.
Bug 2 — EPO CQL was sending infrared as the first AND term. This is the more damaging bug. EPO evaluates AND chains left to right — the first term determines the initial result pool. infrared alone matches patents about medical imaging, display backlights, security cameras, building thermography, and automotive sensors all at once. By the time lane detection was applied as the second AND filter, EPO had already returned its 50-result cap filled with unrelated patents. lane detection as a filter on an already-capped result set doesn't help.

What changed
token_extractor.py — added a new epo_search_order field to ExtractedTokens. The _specificity_sort() function scores terms by discriminating power: multi-word phrases score highest (+10 per word), terms not in _LOW_DISCRIMINATING score higher (+8), length adds to the score. For the AV query, the deterministic baseline already produces the right order: autonomous vehicle → lane detection → infrared. This is correct even before the Claude pre-call runs.
prompts/identify_primary_token.txt — updated to ask Claude for epo_search_order in addition to primary_token. The two serve different purposes: primary_token constrains expansions, epo_search_order drives the CQL. Also added explicit rules so Claude doesn't pick generic sensor types as primary when the invention is about what the sensor detects.
query_expansion.py — the Claude pre-call now reads epo_search_order from the response and writes it onto tokens.epo_search_order, overwriting the deterministic baseline with Claude's context-aware ordering when available.
epo_search_service.py — _build_cql() now simply trusts that the list it receives is already ordered correctly (most discriminating first), and the tiered fallback strategy was upgraded: Tier 1 uses all terms, Tier 2 drops the least discriminating (last) term, Tier 3 uses only the top two, Tier 4 is OR relaxation. The max_results cap was also raised from 25 to 50 to give cosine+BM25 more to work with.
patent_pipeline.py and streamlit_app.py — both now pass tokens.epo_search_order to epo_fetch_by_keywords. The Tab 1 info panel now shows the EPO search order explicitly as autonomous vehicle → lane detection → infrared so you can verify it's correct before running.
